# Limitations

The following limitations apply to the current version of Venture AI. They are stated honestly and should be referenced in any academic submission or demo.

## 1. Synthetic Dataset

All models were trained on **synthetic development data** generated by scripts in `ai-service/training/`. No real startup, investor, or investment outcome is represented.

**Consequence:** every evaluation metric in this project (MAE, R², ROC AUC, Precision@5, NDCG@10, accuracy) describes model fit on generated data. None of them predict real-world performance.

## 2. Not Financial Advice

The AI models output analytical estimates. They do not constitute investment advice, financial advice, or a recommendation to invest. This is stated in the disclaimer returned by the FastAPI service and rendered in the UI.

## 3. Recommendation Direction

The two-tower recommender is trained **investor → startups**. Given an investor's profile, it ranks startups.

- The STARTUP-facing "Investor Matches" page is therefore a **placeholder** in the current version.
- Reversing the direction (startup → investors) would require a trained reverse model and is out of scope.

## 4. Pitch Analyzer Behavior on Real Text

The BERT pitch analyzer was fine-tuned on templated synthetic pitch-deck text. It performs well on that distribution (near-perfect section classification on the held-out test split). On free-form professional prose it returns low-confidence predictions and may report sections as missing even when they are present in a different vocabulary.

This is expected behavior for a synthetic-data model. It is not a bug.

## 5. Dataset Size

The startup prediction dataset has ~300 unique records. The recommender's interaction set is larger (~4,200 pairs) but still synthetic. Both are small by industry standards. Real deployments would require orders of magnitude more data plus careful bias analysis.

## 6. No Real-World Validation

No evaluation has been conducted against real startups, real investors, real pitch decks, or real investment outcomes. Real-world validation is a prerequisite before any production use.

## 7. Production Compliance

Deploying a system like this in a real financial context would require:

- Legal review (securities regulations, GDPR, data residency)
- Regulatory compliance (SEC / SEBI / FCA equivalents)
- Fairness and bias audits
- Explainability guarantees for automated decisions
- Human-in-the-loop review

None of these are implemented.

## 8. Infrastructure Limitations

- **Backend has no `/actuator/health` endpoint.** The Docker healthcheck uses an HTTP probe against `/` and treats a 401 response as liveness. This is a working pattern but less precise than a dedicated health endpoint.
- **BERT model size (438 MB)** prevents straightforward GitHub upload. Git LFS or external artifact hosting is required.
- **Host port remapping (backend 8081, MySQL 3308)** is necessitated by local service conflicts. Container-internal ports remain the standard 8080 / 3306.

## 9. No Real-Time Features

The current system does not provide:

- Real-time notifications
- Messaging or chat
- Live model updates
- Streaming inference

Everything is request/response.

## 10. No Persistence of AI Outputs

The AI service returns predictions but does not store them. The database does not keep a history of predictions, recommendations, or pitch analyses. Analytics pages recompute from live calls.

## 11. Authentication Model

JWTs are stored in `localStorage`, which is vulnerable to XSS in a production setting. A production-grade version would use httpOnly cookies with CSRF protection. For an academic project, localStorage is acceptable.
